# 결함 수정 (Defect Correction)

Zeller의 체계적 디버깅(TRAFFIC)을 이 레포 실측 궤적에 맞춘 절차. **각 단계 뒤에 검증을 끼워** 매 단계 후 시스템이 작동 상태로 남는다.

## 절차

1. **재현** — 실패를 재현하는 최소 명령을 확보한다.
   - ✔ 그 명령이 *실패하는 것*을 직접 확인했는가? **재현 불가면 여기서 중단**하고 인간에게 묻는다(추측 수정 금지).
2. **최소화** — 재현 케이스를 줄인다(입력·범위·파일 수). 절반씩 줄이며 실패 유지 여부를 확인.
   - ✔ 최소화 후에도 같은 실패가 재현되는가?
3. **기원 추적** — 실패 지점에서 역방향으로 의존을 따라 **읽는다**. 이 단계에서는 편집하지 않는다.
4. **격리** — 가설 하나 → 예측 → 실험 → 관측. **한 번에 하나만** 바꾼다.
   - ✔ 예측이 빗나가면 가설을 버리고 3으로 돌아간다(고치려 들지 말 것).
5. **수정** — 감염 사슬의 원인 지점만 최소 변경.
   - ✔ 2의 최소 케이스가 통과하는가?
6. **회귀 고정** — 최소 케이스를 테스트로 커밋한다. 없으면 같은 결함이 돌아온다.
7. **전체 검증** — 기존 스위트 + 게이트 전부 그린.

## 종료 조건

아래를 **모두** 만족해야 종료:
- 최소 재현 케이스가 존재하고, 감염 사슬(원인→실패)이 한 줄로 진술됨
- 최소 케이스를 담은 회귀 테스트가 커밋됨
- 기존 테스트 스위트 그린 — **기대값을 바꾸지 않은 채로**
- 게이트 그린(`node scripts/health.js`)

## 이탈 조건

- 재현 불가 → 중단, 인간 확인
- 요구가 "동작을 바꿔 달라" → 기능 추가 시나리오로 전환
- 동작 보존한 채 구조만 변경 → 구조 리팩토링 시나리오로 전환

전환 시 **전환 사실과 근거를 남긴다**(작업은 태생적으로 다중 범주라 전환은 정상이다 — 은폐가 문제다).
