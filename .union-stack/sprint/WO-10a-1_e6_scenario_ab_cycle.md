# [WO-10a-1] E6 시나리오 A/B 1사이클

## 목표
`eval/PROTOCOL.md` §3-bis(E6)의 **팔 ①(시나리오 없음) 대 팔 ②(시나리오 강제)** 를 각 5런 돌려
`[TOOL-17]` 결함수정 시나리오의 **내용 가치**를 기계 판정한다. 팔 ③(자가 선택)은 카탈로그가
2개 이상일 때만이므로 이번 사이클 **범위 밖**이다.

> **왜 WO인가.** 이 항목은 HANDOFF에 2세션 체류했고 3세션째에 걸렸다([PRO-13] §4-4).
> 미착수의 원인은 우선순위가 아니라 **실행 주체**다 — 10런은 팔마다 격리된 전사 디렉터리의
> top-level 세션이어야 하고 발화가 1건으로 묶여야 해서, 세션 안의 에이전트가 자기 세션에서
> 대신 돌릴 수 없다. 그래서 HANDOFF(휘발)에서 빼 **인간이 집어 들 수 있는 작업 지시**로 고정한다.

## 수용 기준
- D1~D5를 **두 팔에 같은 순서로** 배분하고, 워크스페이스는 팔별로 따로 만든다(경로가 갈려야 전사도 갈린다).
- 런 1개 = 과제 1건 = **발화 1건**. 추가 발화는 분모 오염이므로 금지.
- 팔 ②는 세션 시작 시 인간이 `[TOOL-17]`을 지정한다(`activation: manual`).
- 각 런 종료 후 `verify`가 exit 0(숨은 오라클 통과 = 정답)인지 기록한다.
- 10런 완료 후 `eval-arm`이 성공 바(**턴 또는 토큰 유의미 감소 AND 품질 비악화**)를 기계 판정한다.
- 델타 ≤ 0이면 반증 처리 경로를 탄다 — 시나리오 v1 개정 1회, 그래도 ≤ 0이면 아키타입 폐기 + 원장 기록
  (§3-bis 반증 처리). **결과가 음수여도 이 WO는 성공적으로 닫힌다** — 재는 것이 목표이지 이기는 것이 아니다.

## 절차
```bash
node scripts/e6-workspace.js list                       # 과제 목록
node scripts/e6-workspace.js build D1 <팔디렉터리>/D1   # 워크스페이스 + 발화 출력
node scripts/e6-workspace.js verify D1 <팔디렉터리>/D1  # 세션 종료 후 정답 판정
node scripts/eval-arm.js <①전사디렉터리> <②전사디렉터리> --n 5   # 10런 후 최종 판정
```
운영 상세는 `eval/e6-suite/README.md`. 계측기는 `[TOOL-18]`(품질) · `[TOOL-19]`(비용) · `[TOOL-20]`(스위트).

## 증거
닫을 때 `eval-arm` 출력(델타·n·유의성·품질 비악화)을 frontmatter `evidence:`에 적고,
`eval/RESULTS.md` §E6에 결과를 싣는다(팔 전사 실데이터는 `PROTOCOL` §4상 싣지 않는다).
통과한 델타는 `[TOOL-17]` 카드의 `evidence[]`에 `{eval_run, delta, n, date}`로 고정한다.

## 한계 (결과를 읽을 때 함께 읽을 것)
결함 5건은 전부 **순수 함수 국소 결함**이다. 다중 모듈·경합·타이밍 결함으로 일반화하지 말 것.
오라클은 *이 체크아웃의* 테스트 파일이므로 레포가 그 파일을 고치면 오라클도 바뀐다.
