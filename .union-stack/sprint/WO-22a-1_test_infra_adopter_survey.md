# [WO-22a-1] 테스트 축 하류 설문 회수

## 목표
[PRO-22] 의 가설 H1~H5(실행·영수증·기준선·약화·카탈로그)를 **사용자 측 증언**으로 판정한다.
대상은 통합 테스트 인프라가 가장 두터운 어답터 2곳이다(예시 아님 — 실어답터. 공개 평면이라 이름은
적지 않는다. 설문 파일의 로컬 위치는 에이전트 비공개 메모리에 있다 — [ADR-11] 경계).

> **왜 WO인가.** 답변 주체가 이 세션이 아니라 **각 어답터 레포의 에이전트**다([WO-10a-1] 과 같은 이유 —
> 실행 주체가 다르면 HANDOFF(휘발)가 아니라 인간이 집어 들 작업 지시로 고정한다).

## 수용 기준
- 두 어답터의 `.union-stack/spike/SPIKE-harness_test_infra_survey.md` 에 `## 답변` 절이 채워졌다
  (문항마다 사실·근거 경로·의견·확신도 — 설문 머리의 답변 규칙).
- [PRO-22] §2 의 H1~H5 각각에 판정(채택/보류/기각)과 근거 문항 번호가 기록됐다(§6 판정 규칙).
- 설문이 새로 드러낸 요구(가설 밖)는 [PRO-22] 개정안 또는 별도 PRO 후보로 라우팅됐다.
- 두 spike 가 종료됐다 — 답변이 [PRO-22] 로 증류된 뒤 **어답터 쪽에서** 폐기(spike 종료 규칙).
  상류 평면에는 익명 집계만 옮긴다(공개 레포).

## 절차
1. 인간이 각 어답터 레포에서 세션을 열고: "`.union-stack/spike/SPIKE-harness_test_infra_survey.md` 질문지에 답해줘".
2. 상류 세션이 두 답변 파일을 읽어 H1~H5 판정표를 [PRO-22] 에 추가(version 0.2).
3. 판정 후 인간이 [PRO-22] 를 승인/기각 — 승인 시 §3 구현 순서대로 WO 를 발행.

## 증거
- 두 답변 파일(어답터 로컬) + [PRO-22] v0.2 의 판정표 커밋.
