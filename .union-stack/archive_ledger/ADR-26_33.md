# Architecture Decision Ledger — ADR-26 ~ ADR-33 (rotated 2026-08-20)

- [2026-08-20][ADR-26]: 대시보드 뷰 라우팅을 **JS → CSS로 이전**(라디오 `:checked ~` 형제 선택자, 진입점 7개 전부 `<label>`) — 스크립트를 실행하지 않는 뷰어에서 축 페이지에 **도달 불가**였다. [TOOL-25] 카드는 "클릭이 정본, 해시는 부가"라 적었으나 **클릭 핸들러도 JS다**: 관측된 증상(해시 미유지)의 원인을 해시로 오귀속해, 같은 결함을 두 번 고쳤다(1차: 전 뷰 `hidden` → 빈 화면. 2차: 클릭 핸들러 → 전환 불가). 판별 질문은 "무엇이 전환을 *수행*하는가"이지 "무엇이 전환을 *지시*하는가"가 아니다. 내구성 3단으로 재설계: JS+CSS → 기존 동작 + 해시 북마크 / JS 죽음 → **전환 성립**(CSS) / CSS까지 죽음 → 전 뷰가 쌓여 내용은 읽힘. 검증은 단언이 아니라 **스크립트 제거 사본의 실클릭**으로 했다(단언은 1차 수리도 통과시켰다 — 계측기가 자기 가정으로 눈멀던 [ADR-07]·[ADR-23]·[ADR-24] 병리의 네 번째 사례이며, 여기서 눈먼 가정은 "테스트 환경 = 배송 환경"이다). 어답터 실사용 보고에서 발견 — 상류 자기 사용만으로는 브라우저에서만 열어 보므로 영원히 안 보인다.
- [2026-08-20][ADR-27]: 상류 테스트가 **상류 인스턴스 픽스처를 무조건 단언**하던 4건(`dashboard`·`lineage-tree`의 `WO-10a-1`, `tool-linter`의 더미 `TOOL-01`, `e6-workspace`의 `eval/e6-suite`)을 **픽스처 부재 시 건너뛰도록** 전환 — 어답터 레포에서 4스위트가 실패했다(실측). 삭제가 아니라 조건화를 택했다: 상류에는 픽스처가 있으므로 단언이 그대로 실행되어 **커버리지가 보존된다**(실측: 건너뜀 0건, 단언 수 유지). 순수 함수 단언은 양쪽에서 무조건 돈다. `TEMPLATE_BITS` 목록 확장으로 푸는 길은 기각했다 — 그 길은 어답터에서 스위트를 *삭제*해 순수 함수 커버리지까지 함께 잃는다.
- [2026-08-20][ADR-28]: 누설 게이트를 **소프트 의존**으로 전환(`health`·`ref-linter`·`gate-contract.test`) — `init --drop-template-bits` 가 `leakage-guard.js` 를 삭제하는데 세 곳이 하드 require 해서, **문서화된 도입 경로를 따른 어답터에서 `node scripts/health.js` 가 통째로 크래시**했다(실측: `Cannot find module './leakage-guard'`). 하네스 자기 점수표가 모든 어답터에서 죽어 있었고, 상류 자기 사용만으로는 파일이 항상 있으므로 영원히 안 보인다. 부재 시 게이트는 `INFO 해당 없음`으로 낸다 — `OK` 로 위조하면 통과와 관측 불가가 같아지고, `FAIL` 로 두면 실콘텐츠가 정상인 어답터에서 트립와이어 의미가 반전된다([ADR-23]의 "관측 불가는 통과가 아니다" 문법). `ref-linter` 의 면제는 구조적 면제(`_GUIDE`)만 남긴다 — 더미 마커·METHODOLOGY 는 템플릿 개념이고, 어답터에선 전부 실콘텐츠라는 판정이 옳은 기본값이다. `gate-contract.test` 는 **파일 부재만** 건너뛴다(존재하는데 require 가 던지면 그대로 터진다 — 고장을 조용히 넘기지 않는다). env 플래그(`TEMPLATE_MODE`) 방식은 기각: 어답터가 설정을 기억해야 하고, 파일의 존재 여부가 이미 정확한 신호다. 부수 관측: ARCH-00 을 인용하는 게이트는 `leakage-guard` **하나뿐**이라 어답터에서 무게이트가 된다 — 실제 네이밍 집행자(`zfs-linter`)가 소스에서 ID를 인용하지 않는 인용 공백이며, "인용 ≠ 집행" 경고의 실사례다(별건).
- [2026-08-20][ADR-29]: 어답터 **설정 표면** 신설(`.union-stack/adapter.json`, `scripts/adapter.js`) + `template-update` 의 **3-way 로컬 개조 보호** — 어답터 이슈 #1. sync 카테고리의 전제("덮어써도 잃을 것이 없다")가 실전에서 거짓이었다: LifeSaju 어답터는 sync 파일에 정당한 개조 3건을 반복 재적용 중이었고 `--apply` 가 그중 2건을 조용히 덮어써 게이트 2개가 즉시 FAIL 했다(naming + leakage). 진단은 "개조가 나쁘다"가 아니라 **개조를 담을 표면이 없었다**이다. 둘로 닫는다. ①설정 흡수 — `private: true` 는 health 의 leakage 판정을 FAIL→INFO 로 강등하고(누설 가드는 *공개 템플릿* 보호용이라 비공개 실콘텐츠 레포에선 의미가 반전된다), `zfsIgnored` 는 zfs-linter 면제 목록에 합산한다. 게이트 자체는 손대지 않는다 — 강등은 *점수표의 판정*이지 게이트의 술어가 아니다([ADR-28]의 "관측 불가 ≠ 통과" 문법의 연장). 위치가 `.union-stack/adapter.json` 인 이유는 `classifyPath` 가 이 경로를 **불가침**으로 분류해 상류가 영원히 안 건드리기 때문이다(`package.json` 필드 안은 그 반대 — review 카테고리라 상류 변경과 어답터 설정이 같은 파일에서 충돌한다). 알 수 없는 키·형식 오류는 조용히 무시하지 않고 경고로 낸다(적용된 줄 알았는데 아닌 오타가 이 부류 설정의 표준 사고). ②앵커 대조 — `로컬 vs 마지막 정합 앵커 vs 상류` 3-way 로 `clean/modified/unknown` 을 가르고 `--apply` 는 clean 만 쓴다. 앵커(`.union-stack/template-sync.json`)는 `--apply` 가 쓴 파일의 **상류 sha** 를 기록하고 `init.js` 가 클론 시점(로컬 == 상류)에 시딩한다. 앵커 없는 파일을 `unknown` 으로 두고 **역시 건너뛰는** 것이 핵심 결정이다 — 판별 불가를 통과로 위조하면 이 ADR이 고치려는 사고가 그대로 재현된다. 기존 어답터는 첫 회 `--force` 가 필요하고(⚠ 마이그레이션), 그 한 번 이후로는 개조만 골라 보존된다. 흡수되지 않는 개조도 있다: 어답터의 `harness.yml` 주석("관찰 전용")은 정책 서술이라 설정 대상이 아니다 — review 로 남긴다.
- [2026-08-20][ADR-30]: 자기 테스트의 **템플릿-평면 단언**을 계약 단언·픽스처 감지로 치환 + `npm test` 글롭화 — 어답터 이슈 #2. [ADR-27]이 4건을 조건화했으나 **부류가 남아 있었다**: `init --apply` 직후의 신선한 어답터에서 3스위트가 여전히 실패했다(`check-prereqs` 의 더미 계보 `01a`, `dashboard` 의 섹션·파일명 3건, `ref-linter` 의 원장 행·게이팅 2건). 처방을 셋으로 나눴다. ①**계약으로 승격** — "개요에 8섹션이 전부 있다"를 "섹션은 원자료가 있으면 그리고 없으면 빠진다"로 바꿨다. 이건 어답터 호환이 아니라 **더 강한 단언**이다: 계약 0인 레포에서 빈 계약 카드를 그리는 쪽이 결함인데 기존 단언은 그걸 못 잡았다. 크기 절의 `archive_ledger.md`, 원장의 `ADR-02` 같은 **하드코딩 값**도 데이터에서 읽어(`sizes[0].file`, 원장의 실제 행 앵커) 같은 성질을 얻었다. ②**픽스처 감지** — 계보 전거 검사는 그 계보가 실재할 때만 돈다. ③**모드 감지**(`adapter.isTemplateRepo`, `package.json` name) — "게이팅 대상 0" 처럼 개별 픽스처로 환원되지 않는 *템플릿 청결도* 단언에만 쓴다. 셋 중 ③을 최후로 미룬 이유: 픽스처를 직접 보는 검사는 자기가 무엇을 필요로 하는지 스스로 말하지만, 전역 모드 플래그는 말하지 않는다. 부수 수정: `npm test` 가 34개 파일명을 하드코딩해 `--drop-template-bits` 로 2개가 사라진 어답터에서 **첫 파일에서 죽었다** — `node --test "scripts/*.test.js"` 로 글롭화(⚠ package.json 은 review 라 어답터가 수동 반영). 검증: 어답터 시뮬레이터(작업트리 사본 + `init --apply --drop-template-bits`)에서 **33스위트 전량 green**, 상류에서도 무회귀. 이 시뮬레이터가 [PRO-17] 어답터 팔의 수동 선행 실행이다 — 팔 자체는 여전히 승인 대기.
- [2026-08-20][ADR-31]: HISTORY **헤딩형 항목 인식**(`history-linter.parseHeadingEntries`) — 어답터 이슈 #3. `MIGRATION.md` 경로로 이관한 어답터는 HISTORY 를 `### YYYY-MM-DD — 제목` + context/decision/rationale/impact 로 갖는 것이 자연스러운데, 파서가 표만 보므로 대시보드 시간축이 **전략 분기점 0**을 표시했고 린터는 다른 불변식(사실+근거)만 보므로 형식 불일치가 조용히 지나갔다. 즉 *"분기점을 안 쓰는 프로젝트"와 "형식이 다른 프로젝트"가 구분되지 않았다* — [ADR-23]이 "설정 파일 부재는 0이 아니라 관측 불가"로 닫은 것과 같은 병리의 콘텐츠 축 사례. 판정을 셋으로 가른다: **계수는 두 형식 모두**(조용한 0 제거), **차단(REJECT)은 표 형식만**(표는 컬럼이 곧 계약이라 "근거 칸이 비었다"가 사실이다), **헤딩형의 근거 미검출은 CLARIFY**(자유 서술에서 부재를 단정하면 미탐을 오탐으로 바꾼다 — [PRO-07] 문법). 라벨 매칭은 관대하게(하위 헤딩·목록·굵은 라벨, 한국어/영어) — 놓친 근거는 CLARIFY 한 줄이지만 놓친 *항목*은 "분기점 0"이라는 **거짓 사실**이 된다. CLI 는 `toShellExit` 로 접어 `npm run lint` 사슬을 끊지 않는다. 대시보드는 근거 없는 행을 빈 칸이 아니라 표식(`근거 미검출 — CLARIFY`)으로 낸다. 부수 수리: `handoff-linter` 의 5부 매칭이 키워드 단독이라 §2 "변경 위치 (… **진입점**)" 이 `next` 의 `/진입/` 에 먼저 걸렸다 — 존재 여부만 볼 때는 안 드러나지만 본문을 꺼내 쓰는 순간(제품 축이 §3·§4 를 읽는다) 틀린 절을 준다. 문서 순서 그리디 배정으로 수정.
- [2026-08-20][ADR-32]: 대시보드 **섹션 컴포지션 확장점**(`--sections <module>`) — 어답터 이슈 #4. `dashboard.js` 는 sync 파일이라, 어답터가 자기 관측(제품 KPI·도메인 지표)을 한 장에 합치려면 선택지가 ⓐ sync 포크(→ 다음 `--apply` 가 되돌림, [ADR-29]가 고치는 바로 그 사고) ⓑ HTML 2장(합성 원칙 훼손) 뿐이었다. 계약: 모듈이 `[{id, title, axis, axisLabel?, render(gathered)}]` 를 export 하고 `render` 는 **수집 데이터 → HTML 조각**의 순수 함수다. 두 경계가 결정적이다. ①**카드 껍데기는 호스트가 씌운다** — 어답터 섹션이 `<section>` 을 직접 열면 페이지 구조를 깨뜨릴 수 있고, 그러면 확장점이 사고 표면이 된다. ②**실패는 국소화** — 던지는 섹션은 그 카드에만 오류를 적고 나머지 페이지는 산다(전체 불사). `axis` 가 기존 축이면 덧붙고 새 id 면 축(나브+라디오+CSS 규칙)이 하나 생긴다 — 그래서 `VIEWS`·`ROUTER_CSS` 를 모듈 상수에서 함수(`buildViews`·`routerCss`)로 승격했다. 모듈 로드 실패는 조용히 넘기지 않는다(경로 오타가 "내 섹션이 없네"로 끝나는 것이 이 부류 확장점의 표준 사고): 보고 + exit 1, 단 대시보드는 나머지로 계속 낸다.
- [2026-08-20][ADR-33]: 대시보드 **제품 축**(5번째 축) 신설 — 어답터 이슈 #5. 현행 4축의 관객은 전부 하네스 관리자다(게이트·예산·의례·결정 밀도). PO 의 네 질문 — 로드맵 대비 어디까지 왔나 · 뭐가 진행 중이고 뭐가 막혔나 · 최근에 뭐가 나갔나 · 리스크는 무엇인가 — 에는 어느 축도 답하지 않았고, **원료는 전부 평면에 이미 있었다**(계산이 아니라 합성 공백 — 이 도구 자신의 설계 원칙 그대로). 섹션 6: 단일 진입점(HANDOFF §3) · 로드맵 진행률(PHASE 의 exit 절) · Now/Next/검증대기(WO `status:`) · PLAN 롤업 · 최근 배송(원장 + `feature/live.md`) · 리스크(Verifying 잠금 + 게이트 부채 + HANDOFF §4). 새 수집을 만들지 않는다 — 이미 모인 축에서 파생만 한다. **관측이지 판정이 아니다**([PRO-11] §4 측도 금지): exit 충족은 산문의 `✅` 표식에서 읽은 휴리스틱이고 진행률을 점수로 승격시키지 않는다. 두 표기 결정이 그 규율의 이행이다 — ①exit 기준이 0건인 단계는 "달성"이 아니라 **기준이 없다**는 사실로 적는다 ②전 단계가 종료면 `current` 를 마지막 단계로 위조하지 않고 "후속 단계 미정"으로 낸다(로드맵이 끝났는데 후속이 없다는 것이 PO 가 볼 신호다). 계수기 오염 회피: exit 줄은 **키워드로 시작하는 항목**만 센다 — 본문의 단순 언급까지 세면 진행률이 산문 밀도를 따라 부푼다([ADR-07] 계열).
