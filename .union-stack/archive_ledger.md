- [2026-08-20][ADR-37]: [ADR-35] `prose` 의 **절단 경로 2건 + live 표 헤더 오계수** 수리 — 어답터 제보. 셋 다 상류 데이터 형상에서는 영원히 안 보이는 자리다([ADR-26]~[ADR-28] 계열의 다섯 번째). ①**구분자 절단**: 요지는 `split(' — ')[0]` 로도 잘리는데 [ADR-35]는 *길이* 절단(`clip`)만 수습했다. 어답터 원장 관례가 `**제목 — 부제**`(볼드가 구분자를 감싼다)라 조각에 여는 `**` 만 남고, 그 조각이 상한보다 짧아 `clip` 이 손댈 기회조차 없었다 — 최근 배송 6건 전부, 전체 15건 노출. 상류 관례는 `**제목** — 부제`라 안 걸린다. 처방: 절단을 한 곳(`gistOf`)이 소유하고 **자른 쪽이 자기가 깨뜨린 마커를 수습한다**(자르지 않았으면 손대지 않는다 — 원문의 짝 없는 마커는 작성자의 것이고 `prose` 안전 폴백 소관). ②**수리 방향 전환 — 떼어내기 → 닫기**: 첫 구현 `trimDanglingMarker` 는 마커 경계까지 물러났는데, 여는 마커가 맨 앞이면(`**제목 전체가 볼드**`) `lastIndexOf` 가 0이라 **텍스트를 통째로 지웠다**(실측: 말줄임만 남음). 제보엔 없던 자기 발견이며, 어답터 사례가 조금만 길었으면 노출 대신 *소실*로 나타났을 자리다. `closeDanglingMarker` 로 바꿔 닫으면 한 글자도 안 없어지고 조각이 의도대로 읽힌다 — 절단의 목적은 짧게 보여주는 것이지 지우는 것이 아니다. ③**live 표 헤더 오계수(표시가 아니라 숫자가 틀림)**: `parseLiveRows` 가 헤더를 *어휘*(`feature`…`status`)로 판정해, 한국어 헤더를 못 알아보고 파일에 표가 여럿이면 두 번째부터 전부 놓쳤다. 어답터의 존별 표 13개에서 헤더가 하나도 안 걸러져 PO 타일 **배송 122 = 실제 109 + 헤더 13**. 판정을 마크다운의 실제 계약인 **"다음 줄이 구분선"**으로 바꿨다(`history-linter` 가 쓰는 규칙 재사용, 언어 무관). 같은 자리에서 열별 처리 불일치도 정합 — `nm` 만 `prose` 를 거치고 `ref`·`status` 는 `esc` 라 같은 행에서 한 열만 마커가 렌더됐다. 표의 세 열은 전부 평면 산문이므로 셋 다 `prose`. 검증: 제보된 데이터 형상(존별 표 13개 + `**제목 — 부제**` 원장)을 사본에 실제로 주입해 재현 → 수정 후 **계수 122→109, 렌더 본문 원문 마커 0**. 회귀 22단언. **가드는 약화하지 않았다** — `dashboard.test.js` 의 "렌더 본문 원문 마커 0"은 실평면(`gatherAll()`)을 입력으로 받고 그래서 이 결함들을 잡았다.
