# [PRO-12] 신뢰도 티어 — 위임 확대의 조건

## 1. 요지
인간이 에이전트에게 **문서 작성 자체를 위임**할 수 있도록 Schema 생성·편집 조건을 완화하되,
완화의 대가로 모든 ZFS 문서에 **신뢰도 티어 축**을 신설해 "누가 어디까지 믿어도 되는 문서인가"의
위계를 기계 판독 가능하게 만든다. 완화와 게이트는 **한 몸**이다 — 게이트 없는 완화는 fail-close 붕괴,
완화 없는 게이트는 표기 관료제.

## 2. 티어 축 (frontmatter 오버레이)
```text
tier: draft      에이전트 자유 생성·편집. 규범 효력 0 (proposals와 동일 의미론).
tier: reviewed   인간이 읽고 스탬프. 참고 효력 — 구속하지 않는다.
tier: ratified   Approved-by 스탬프. 에이전트를 구속하는 규범. 편집은 현행 규칙(GRANT/개별 승인) 유지.
```
- 티어명·전이 조건은 하네스 자체 정의다. 정본 [AXIOM-13] 생명주기의 **꼴만** 참조(값 반입 금지, [LSN-05] 격리).
- 정본 반입 정책과 동형: "accepted만 정박"([PRO-11] §2) ↔ "ratified만 구속".

## 3. 완화의 정확한 범위
1. 에이전트는 Schema 경로에 **`tier: draft` 문서를 재승인 없이 생성·편집할 수 있다.** (현행: proposals 레인만 가능)
2. `draft → reviewed → ratified` **승격은 인간만** 한다. 에이전트 커밋이 tier를 올리면 게이트가 REJECT — [PRO-09] GRANTS의 자기부여 방지와 동형.
3. `ratified` 문서의 편집 규칙은 **현행 유지** — 이 제안은 ratified 문턱을 낮추지 않는다. 낮추는 것은 "draft가 존재할 수 있는 장소"뿐.

## 4. 게이트 (trust-tier gate — permission-guard 확장)
[PRO-11]의 4값 결과와 그 **차단 정책**(REJECT만 차단)을 전제로 한다.
이 게이트에서 흐름을 중단시키는 판정은 **자기승격 REJECT 하나뿐**이다 — 드물고 명백히 위험한
행위만 막고, 나머지는 전부 표면화다:
- 에이전트 커밋의 tier 자기승격 → **REJECT** (유일한 차단)
- Schema 경로 신규 문서의 tier 미기입 → **CLARIFY** — 질문 병기 후 진행, 커밋을 막지 않는다.
  기존 문서는 소급 표기 의무 **없음**(`ratified` 간주) — 소급 라벨링 노역은 그 자체가 마찰이다.
- `draft` 문서의 Upward Fetching 주입 → **배너 부착 후 포함** (기본 제외가 아니다 — 방금 쓴 초안이
  다음 세션에 안 보이는 컨텍스트 기아는 위임 완화의 목적을 정면으로 거스른다)
- `health.js`에 티어 분포 지표: `draft N · reviewed N · ratified N` (draft 적체의 조기 검출 — 관측만)

## 5. 반증 조건
- draft 남발로 Schema 도메인이 비규범 문서에 잠식(draft 수가 ratified 수를 지속 초과하며 승격률 정체)되면, 완화가 위임이 아니라 잡음 생산이었다는 뜻 → 완화 철회, 티어 축만 존치.
- 티어 도입 후에도 에이전트가 draft를 규범으로 오인·인용하는 사고가 발생하면 배너 방식 재설계.
- **마찰 회귀**: `session-friction.js` 기준 문서 작성 의도의 왕복 비용이 도입 전보다 늘면
  (위임 완화인데 승인 왕복이 늘었다면) 게이트 배선이 목적을 배반한 것 → CLARIFY 지점 축소.

## 6. Split-principle check
(a) "없는 시스템이 없는가" — 해당 없음을 확인함: 이것은 기둥이 아니다.
(b) "기존 셀에 안 들어가는가" — 들어간다: frontmatter **오버레이**다([PRO-04] 판례 — 기둥 기각·오버레이 수용과 동일 결론). 신규 도메인·평면 없음.
