# [PRO-20] WO 의 계보 밖 축 선언 (`axis:`)

## 1. 배경 — 실측된 공백 (하류 이슈 #8, LifeSaju 2026-08-20)

어답터가 WO 11건을 발행하며 관측: WO 가 실제로 되써야 할 문서(`FLOW-04` 의 특정 단계)가
**계보 밖(ID 04 vs WO 계보 01e)** 이라 두 의례 모두에서 안 보였다.

- **진입**: `upward-fetch WO-01e-1` 은 계보 산술로 `FLOW-01`(의미상 무관)을 끌어오고,
  정작 필요한 `FLOW-04` 는 못 싣는다.
- **종료**: `work-close` 의 후보 목록에 `feature/flow/` 가 없었다 — 이것은 이슈 #8 제안 ① 로
  이미 닫혔다(후보 추가, [ADR-50]). 그러나 후보는 *디렉터리*를 가리킬 뿐, **어느 FLOW 문서인지**는
  여전히 세션의 기억에 있다.

어답터는 WO 마다 `## 상위 축` 절을 손으로 달아 메웠다 — 규율이지 구조가 아니다.

## 2. 선례 — 같은 구조적 필요의 세 번째 사례

계보 산술(트리)이 못 보는 간선을 frontmatter 한 필드로 선언한 선례가 이미 둘 있다:

| 선례 | 필드 | 방향 | 소비자 |
|---|---|---|---|
| [PRO-16] | `consumers:` | 계약 → 소비자 | blast-radius (영향권·잠금) |
| [PRO-15] | `closed_by:` | WO → 흔적 문서 | work-close (사후 확인) |
| **본안** | `axis:` | WO → 되쓸 문서 | upward-fetch (사전 적재) + work-close (선언·실제 대조) |

`closed_by` 가 *사후 기록*이라면 `axis:` 는 *사전 선언*이다 — 같은 간선의 양 끝이다.

## 3. 채택안

```yaml
# WO frontmatter (예시)
id: WO-01e-1
axis: [FLOW-04, CON-02]   # 이 WO 가 닫힐 때 되써야 할 계보 밖 문서 (브래킷 ID)
```

1. **upward-fetch**: 대상이 WO 이고 `axis:` 가 있으면, 계보 맥락에 더해 선언된 문서를 적재한다
   (`consumers:` 의 WO 판 — 진입 시점에 "무엇을 되쓸지"가 이미 보인다).
2. **work-close**: `closed_by` 가 `axis:` 선언을 커버하는지 대조 — 어긋나면 CLARIFY
   ("선언한 축(FLOW-04)에 흔적이 없다"). 차단 아님, [PRO-15] 문법 그대로.
3. 미해소 `axis:` ID 는 오타이므로 표면화한다(ref-linter 의 브래킷 해소와 같은 논리).
4. 선언은 **WO → 문서 한 방향**만. 역방향 색인은 파생 뷰로만(정본 이중화 금지, [PRO-16] §3-2).

## 4. 분할원리 점검 (신설 아님 확인)

(a) 계보 밖 되쓰기 없는 시스템은 없다 ✓ · (b) 기존 칸에 들어간다 ✓ — 새 기둥·도메인이 아니라
**frontmatter 오버레이**다([PRO-04] 판정 문법). 파일 신설 0, 스크립트 2개 확장.

## 5. 판정 기준 / 재개 조건

- 수용 기준(이슈 #8): `axis:` 선언된 WO 의 진입 의례가 그 문서를 적재하고, 종료 의례가
  선언·실제 불일치를 CLARIFY 로 표면화한다.
- 기각 시: 어답터의 `## 상위 축` 수기 절이 관례로 남는다 — 기각 사유를 이 문서에 보존할 것.
