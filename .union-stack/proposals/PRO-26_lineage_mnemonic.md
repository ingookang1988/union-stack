# [PRO-26] 계보 니모닉 (Lineage Mnemonic)

## 1. 배경 — 루만 ID 는 계산에는 좋지만 사람·냉독 모델에게는 암호다

PO 요청(2026-10-15): 제텔카스텐식 파일명을 **파일명만 봐도 의미가 보이게** 중간 축약어를 두자.

설문 냉독 감사 4건(`eval/SURVEY-01_results.md` §9)이 같은 지점을 짚었다: HANDOFF 의 압축 약어와 `22n5c5g-9` 같은 깊은 ID 는
조상 문서를 열기 전엔 "암호처럼 읽힌다". 사용 모드 답변도 `l`/`o` 제외 규칙 때문에 `k → m`, `n → p` 채번 실수가 반복된다고 했다.
지금 규약(`[DOMAIN]-[LUHMANN_ID]_[slug].md`, [ARCH-00])에서 의미를 싣는 자리는 slug 뿐인데, slug 는 **그 문서**의 뜻만 담고
**계보**(이 01 이 무엇인가)의 뜻은 어디에도 없다. 잎(`WO-01a1-3` — 예시)에서 뿌리(`PLAN-01`)의 뜻을 알 방법이 파일명에는 없다.

## 2. 원리 — ID 는 건드리지 않는다, 의미는 slug 와 뷰에 싣는다

1. **ID 산술 불변.** upward-fetch·blast-radius·isDescendant·플릿 파티션·GC 전부가 ID 문자열에 의존한다([ADR-25] 단일 ID 공간).
   ID 에 글자를 끼우는 순간 도구 전체와 기존 파일이 깨진다.
2. **정본은 코드가 읽는 자리에.** 니모닉 사전을 손표로 두면 썩는다(설문 3/3 "손표는 썩는다"). 루트 문서의 frontmatter 가 정본이고,
   표는 생성 뷰다(tools-index·blocks-index 문법).
3. **소급 리네임 금지.** 기존 파일명을 바꾸면 브래킷 참조가 깨진다(`ref-linter --strict` 가 실존을 요구). 효과는 **생성 뷰**로
   먼저, 파일명은 신규부터.
4. **차단이 아니라 CLARIFY.** 니모닉 없는 루트·접두 없는 slug 는 틀린 것이 아니라 덜 친절한 것이다.

## 3. 채택안 — 새 도메인 0, frontmatter 키 1, slug 규약 1, 린터 CLARIFY 1, 뷰 렌더

### ① 니모닉 정본 — 루트 문서 frontmatter `mnemonic:`
계보 루트(숫자만의 ID — `PLAN-NN` / `PRO-NN` / `PHASE-NN`; 여럿이면 PLAN 우선)가 선언한다. 2~6자 소문자·숫자.
```yaml
# (예시) PLAN-22 frontmatter
mnemonic: auth      # 인증 계보(예시) — 이 계보의 모든 자손이 상속
```
자손은 선언하지 않는다 — ID 산술로 루트를 찾아 상속한다.

### ② slug 규약 — 신규 파일은 `<mnemonic>_<의미>`
`WO-01a-3_auth_token_refresh.md`(예시) 처럼 slug 의 첫 토큰이 계보 니모닉이다. [ARCH-00] 규칙 3 에 **권장 접두**로 추가한다
(Schema 개정 → 승인 트레일러). 기존 파일은 그대로 둔다.

### ③ 린터 — CLARIFY 만
`zfs-linter` 가 ① 루트에 `mnemonic` 이 없는 **활성 계보**(Active/Verifying 자손 보유)와 ② 루트 니모닉이 있는데 접두가 다른
**신규 파일**(`git diff --diff-filter=A` 범위)을 CLARIFY 로 나열한다. 기존 파일은 INFO 집계만. REJECT 없음.

### ④ 생성 뷰에 니모닉 표시 — 파일명을 바꾸지 않아도 즉시 효과
`upward-fetch` 출력 · `sprint/next.md` · `health` 도메인 분포 · `lineage-tree` · `handoff-linter` 의 ID 렌더를
`[WO-01a1-3 · auth]` 꼴로(예시). `query-cli list_docs` 가 **루트별 니모닉 표**를 생성한다(손표 사전 금지).

### ⑤ 채번 보조 — `zfs-linter --next <부모ID>`
`l`/`o` 를 건너뛴 다음 가용 자식 ID 를 제안한다(설문: 채번 실수 반복). 규칙 자체는 유지한다([ARCH-00] 근거: 1/0 혼동).

## 4. 분할원리 점검 ([PRO-04])
(a) 식별자에 사람이 읽을 이름을 덧붙이는 것은 모든 체계가 한다 ✓ · (b) 기존 칸에 들어간다 ✓ — frontmatter 오버레이 1 +
slug 규약 + 린터 CLARIFY + 기존 뷰의 렌더. 새 도메인·ID 공간·파일 0.

## 5. 하지 않는 것
- ⛔ **ID 또는 도메인 접두 변경** — [ADR-25] 유지. `WO-auth01a1-3` 같은 꼴은 도구 전체를 깬다.
- ⛔ **소급 리네임** — 참조 파손. 효과는 뷰(④)가 먼저 낸다.
- ⛔ **니모닉 사전 손표** — 정본은 루트 frontmatter, 표는 생성.
- ⛔ **REJECT 승격** — 니모닉은 친절함이지 정확성이 아니다.
- ⛔ **`l`/`o` 제외 규칙 철회** — 채번 마찰은 ⑤로 푼다.

## 6. 성공 바
- `zfs-linter` 단위 테스트: 니모닉 없는 활성 루트 CLARIFY · 접두 불일치 신규 파일 CLARIFY · 기존 파일 INFO · `--next` 가 `l`/`o` 건너뜀.
- `upward-fetch`·`next.md` 출력에 니모닉이 렌더된다. 니모닉 없는 루트에서는 ID 만(크래시 0).
- 어답터 팔([TOOL-26]) 형상(니모닉 0개)에서 CLARIFY 가 소음이 되지 않는다(활성 계보만 셈).
- 상류 도그푸딩: 활성 계보 전부에 `mnemonic` 선언.

## 7. 미결 (인간 판단)
1. 니모닉 문자 규칙(2~6자 · 소문자 · 숫자 허용?)과 중복 금지 범위(평면 전체 유일?).
2. 루트 정본 우선순위(PLAN > PRO > PHASE)와 루트 없는 계보(WO 만 있는 전역 일련번호 — 설문 C 레포 꼴)의 처리: 니모닉 없음 = INFO.
3. slug 접두를 **필수**로 올릴 시점 — 잠정: 신규 파일 CLARIFY 로 1분기 관측 후.
4. HANDOFF·next.md 의 압축 약어(`G1L` 류)는 이 PRO 범위 밖 — 냉독 감사가 지적한 별개 문제(정의 포인터).

## 8. 하류 검토 반영 (v0.2 — **축소 개정**, 2026-10-15, `eval/SURVEY-02_results.md` §3)

초안은 **상류 형상 전용**이었다. 적용 시험: B 가능(그러나 slug 가 이미 제품 축 접두를 쓴다) · A 절반(활성 5 중 3 만 PLAN 루트 · 잎 ID 루트 ·
우산 WO 루트) · C **0/438**(전역 일련번호). 냉독(antigravity)의 치명 반례: 레거시 번호대가 **도메인별 독립 채번**이라 숫자 루트 니모닉을
상속시키면 무관한 문서에 **거짓 라벨**이 붙는다 — 처음 읽는 모델에게 틀린 라벨은 없는 것보다 해롭다.

**삭제**: ② slug 접두 규약(4/4 기각·보류 — 첫 토큰이 이미 의미 · 사람은 번호로 찾음 · `x_x_` 중복) · ③ 니모닉 린터 CLARIFY(3/4 — 정당한
제품 축 접두·루트 없는 계보에서 영구 소음). ARCH-00 규칙 3 은 **개정하지 않는다**(Schema 승인 불필요).

**유지·수정**
- ④ 뷰 렌더 — 선언이 아니라 **파생 라벨**: 자기 또는 직계 부모 문서의 slug 첫 1~2 토큰(또는 `title`)에서 자동 생성(관리 비용 0).
  자리는 **ID 만 단독으로 나오는 곳**(HANDOFF §2 변경 위치 · next.md · 본문 브래킷 렌더)이고, 파일명이 보이는 곳(디렉터리 · upward-fetch 는
  이미 제목 출력)에는 넣지 않는다. HANDOFF 는 예산 상한을 넘기지 않는 범위에서만.
- ① `mnemonic:` 선언은 **선택적 override** — 루트·중간 노드(`PLAN-56h` 꼴)·우산 WO(`WO-65` 꼴) 어디서나 허용. 유일성 강제 없음.
- 상속 경로 = ID 산술 **+ frontmatter `plan:`·`parent:`**([PRO-27] ③ 전제). 레거시 독립 채번 구간은 **도메인 횡단 상속 금지**([PRO-27] `arithmeticFrom`).
- ⑤ `--next` 는 최하 우선순위(l/o 실수가 커밋에 닿은 사례 0/3).

**ID 유일성 검사**(같은 도메인·같은 ID 파일 2개 — A 에서 2쌍 실존, 상류 린터에도 없던 검사)는 **[PRO-27] ⑤ 로 이관**했다.

**잔여 미결**: 파생 라벨이 사람에게 틀린 뜻을 주는 경우(루트 slug 와 활성 자손 주제가 갈라진 계보 — A 1건)의 처리(override 로 충분한가).
