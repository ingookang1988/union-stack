# [PRO-25] 회고·정리 (Retro & Consolidation)

## 1. 배경 — 매 작업마다 연결하는 것은 비효율이고, 안 하면 누락이 쌓인다

PO 관측(2026-10-15): 가장 활발한 축은 WO·PLAN·HANDOFF 다. WO 는 쌓이고 HANDOFF 는 덮어쓰이며, 그 사이에 **상위 축
(feature/live · verification/derived · CON · PLAN 상태 · LSN · HISTORY)에 반드시 적히거나 연결돼야 할 것**이 빠진다.
그렇다고 작업마다 그때그때 상위 축을 갱신하는 것은 비효율이다 — 종료 의례([PRO-15])는 "흔적 1곳"만 묻는다.

설문 9건(`eval/SURVEY-01_results.md`)이 같은 증상을 3/3 레포에서 보였다:

| 증상 | 관측 |
|---|---|
| 정리 안 된 WO 적체 | `status:` 없음 99/179 · 상태 어휘 38종/438 · `sprint/` 에 438건 미보관 · Verifying 49건 수 주 체류 |
| 교훈 증류 정지 | 224 WO 에 LSN 3건("증류 주기가 너무 느리다") · 계보 밖 교훈은 사설 메모리로(3/3) |
| 생성 뷰·원장 방치 | state.md 50일 미갱신 · CON-00 4개월 미갱신 · 원장 150KB 미회전 · PLAN GC 가 한 번도 Crystallized 에 닿지 않음([ADR-21]) |
| 패턴이 안 모임 | HANDOFF 는 최신만 남아 회차 비교가 없다 · P₁ 후보(session-friction)는 계측되지만 아무도 회차로 읽지 않는다 |

증상의 공통 원인은 **"정리할 시점"이 어디에도 정의돼 있지 않다**는 것이다. 종료 의례는 WO 1건 단위고, 세션 종료는 HANDOFF
1장 단위다. 그 사이 규모(WO 수십 건)에서 돌아야 할 정리가 없다.

## 2. 원리 — 회고는 생성 기계가 아니라 정리 기계다

1. **트리거는 관측이다**([ADR-23] 문법). `health` 가 지표를 보고 "회고 때가 됐다"를 CLARIFY 로 말한다. REJECT 는 없다.
2. **에이전트는 제안하고, 사람이 연다.** 회고 세션은 사람이 "회고 열자"로 시작하는 한 세션이다. 자동 실행이 아니다.
3. **산출은 기존 축에만 쓴다.** 회고가 만드는 새 문서는 회차 기록(ANL) 하나뿐이고, 나머지는 live·gap·state·PLAN 상태·
   archived·원장 회전 같은 **이미 있는 자리**의 갱신이다.
4. **승격은 사람이 한다.** 회고는 LSN·HISTORY·PRO **후보**까지만 만든다(채굴은 P₁ 발견까지 — [ADR-12] 재개 조건을 건드리지 않는다).
5. **하네스 회고와 다르다.** 하네스 회고의 실체는 PRO 결정 로그다(`proposals/_GUIDE`). 이 PRO 는 **제품 평면**(WO→상위 축)의
   정리를 다룬다. 별도 "회고.md"를 만들지 않는다.
6. 시나리오 카드가 아니다([ADR-15] 동결 유지) — 절차는 가이드의 체크리스트, 트리거는 health 차원이다.

## 3. 채택안 — 새 도메인 0, health 차원 1, 설정 키 1, 기록 템플릿 1

### ① 트리거 — `health` 차원 `retro due`
파일에서만 계산한다(전사 없는 도구에서도 돈다). 지표와 잠정 임계(어답터가 `.union-stack/adapter.json` `retro:` 로 덮어쓴다 — [ADR-29]):

| 지표 | 계산 | 잠정 임계 |
|---|---|---|
| 발행 증분 | 전체 WO 수 − 직전 회고 기록의 스냅샷 | ≥ 20 |
| 보관 부채 | `sprint/` 에 남은 Closed WO | ≥ 10 |
| 판정 대기 | Verifying WO 수 | ≥ 10 |
| GC 가능 PLAN | 후속이 전부 terminal 인데 Crystallized 아님 | ≥ 1 |
| 평면 동기화 지연 | plane sync(live·state·gap) 최신 날짜 − 최신 WO 날짜 | ≥ 30일 |
| 증류 정체 | LSN 수 / Closed WO 수 | 상승 없음 + Closed ≥ 30 |

하나라도 넘으면 `retro due: CLARIFY — 사유`. 넘지 않으면 INFO 로 현재 값만. 임계는 측정 전 추정치다 — 2회차부터 어답터
실측으로 조정한다.

### ② 제안 경로
- 에이전트는 `health` 가 CLARIFY 를 내면 HANDOFF §4 에 **"회고 제안 — <사유>"** 한 줄을 쓴다(그 이상 하지 않는다).
- 사람이 "회고 열자"로 세션을 연다. 세션 진입점은 HANDOFF 가 아니라 **직전 회고 기록**(ANL)이다.

### ③ 회고 절차(체크리스트 — `plan/analytics/_GUIDE.md` 에 템플릿으로)
1. **보관**: `sprint/` 의 Closed WO → `sprint/archived/`, `work-close --table --write`.
2. **판정**: Verifying WO 를 사람이 Closed / Active 로 가른다(판정 근거 1줄).
3. **상위 축 흔적**: Closed WO 중 `closed_by` 가 가리키는 축에 실제 행이 없는 것 → live·gap·state·CON 갱신(행 단위).
4. **PLAN GC**: 후속 전부 terminal 인 PLAN → Crystallized → 원장 1행.
5. **교훈 후보**: 같은 꼴 실패 2~3회(evidence `none` 사유 · 재작업 WO · P₁ 상위 버킷) → **LSN 후보 목록**(승격은 사람).
6. **전략 후보**: PLAN 대체(superseded)·의존성 변경 → HISTORY 후보.
7. **위생**: 원장 30KB 초과 시 회전([PRO-18]) · Proposed 로 N일 넘긴 PRO 목록 → 사람 판정.
8. **기록**: ④ 의 회차 기록을 쓴다.

### ④ 회차 기록 — `plan/analytics/ANL-25<x>_retro_<yyyymmdd>.md` (예시: `ANL-25a_retro_20261115.md` · append-only, 절대 재작성 금지)
frontmatter 에 **지표 스냅샷**(①의 6개 + WO 상태 분포 + E3·P₁ 상위 3 — 전사가 있을 때만), 본문에 수행·보류 표와 후보 목록.
회차가 2개 이상이면 `health` 가 **직전 회고 대비 Δ** 를 함께 보여 준다 — 이것이 PO 가 말한 "정량적으로 쌓였을 때의 패턴"이
모이는 자리다. 계보는 이 PRO(25)를 루트로 쓴다([PRO-22]→[WO-22a-1] 과 같은 문법).

## 4. 분할원리 점검 ([PRO-04])
(a) 누적 기록을 주기적으로 상위 축에 접는 절차 없는 시스템은 없다 ✓ · (b) 기존 칸에 들어간다 ✓ — 트리거 = health 차원,
기록 = ANL(append-only 분석 기록, 이미 규정됨), 산출 = 기존 축, 임계 = adapter.json. 새 도메인·티어·카드 0.

## 5. 하지 않는 것
- ⛔ **자동 증류·자동 승격** — [ADR-12] 차단. 회고는 후보까지. 세션 종료 시 자동 실행도 없다.
- ⛔ **매 작업마다 상위 축 갱신 강제** — PO 가 지적한 비효율. 종료 의례의 "흔적 1곳" CLARIFY 는 그대로 두고, 나머지는 회고가 일괄로.
- ⛔ **시나리오 카드 신설** — [ADR-15]. 절차는 가이드 템플릿.
- ⛔ **별도 하네스 회고 문서** — `proposals/_GUIDE` 결정 유지. 이 PRO 는 제품 평면 정리다.
- ⛔ **REJECT 게이트** — 회고를 안 해도 아무것도 막히지 않는다. 안 하면 `retro due` 가 계속 커질 뿐이다(소음이 아니라 부채 표시).

## 6. 성공 바
- `health` 단위 테스트: 임계 미만 INFO · 초과 CLARIFY · 회고 기록 2개 → Δ 출력 · adapter.json 임계 덮어쓰기.
- 어답터 팔([TOOL-26])에 **WO 대량 형상**(Closed 미보관 30 · Verifying 20)을 추가하고 `retro due` 가 사유와 함께 발동.
- 상류 자신에서 회고 1회 실행 → ANL 기록 1건 · 원장 회전 또는 PLAN GC 1건 이상 실제 수행.
- 어답터 1곳 도그푸딩: Verifying 적체(49건)가 판정으로 줄어드는 Δ 가 2회차 기록에 남는다.

## 7. 미결 (인간 판단)
1. 임계 기본값 — 표의 수치는 추정. 어답터 3곳 실측(발행 179·224·438)을 보고 정한다.
2. 트리거 지표를 **발행** 증분으로 둘지 **종료** 증분으로 둘지. 잠정: 둘 다(표).
3. 회고 주체 — 사람 + 에이전트 1세션. 플릿(서브에이전트)로 쪼갤지는 [PRO-05] 파티션 규칙을 따른다.
4. 기록 위치 ANL vs MTG — MTG 는 PLAN 과 같은 계보를 공유해야 해서 평면 횡단 회고에 맞지 않는다. 잠정 ANL.
5. 어답터 배송 — [PRO-24] 경로를 탄다(갱신 도구가 없는 어답터는 회고 차원도 못 받는다).
