# [PRO-17] 어답터 팔

## 1. 배경 — 세 결함이 같은 눈먼 지점에서 나왔다

2026-08-20, 어답터 레포(외부 도입 인스턴스)에서 template-update 후 결함 3건이 보고됐다.
**셋 다 상류에서는 초록이었다** — 스위트 34개 통과, lint 7종 통과, CI 게이트 초록.

| ID | 결함 | 상류에서 안 보인 이유 |
|---|---|---|
| [ADR-26] | 대시보드 축 페이지에 **도달 불가**(스크립트 미실행 뷰어) | 상류는 브라우저에서만 열어 본다 |
| [ADR-27] | 테스트 4스위트가 어답터에서 **실패** | 픽스처(`WO-10a-1`·더미 `TOOL-01`·`eval/e6-suite`)가 상류엔 항상 있다 |
| [ADR-28] | `health.js` 가 어답터에서 **크래시** | `leakage-guard.js` 가 상류엔 항상 있다 |

공통 형태: **"상류 인스턴스에 우연히 존재하는 것"을 코드·테스트·산출물이 암묵 전제**한다.
[ADR-26]은 한 발 더 나간다 — 단언이 1차 수리를 통과시켰다. 테스트 환경(스크립트 실행됨)이
배송 환경(실행 안 됨)과 달랐기 때문이다. 셋 다 **어답터가 보고해야만** 발견된다.

## 2. 제안 — 어답터 형상을 CI에서 한 번 돌린다

`.github/workflows/harness.yml` 에 **어답터 팔** 잡 하나를 추가한다. 새 도구가 아니라
**기존 게이트를 다른 형상에서 한 번 더 돌리는 것**이다(로직 1벌 원칙 유지).

```yaml
# (예시) adopter-arm — init 을 실제로 적용한 사본에서 게이트를 돌린다
- run: node scripts/init.js --name "Adopter Probe" --slug probe --apply --drop-template-bits
- run: node --test scripts/*.test.js      # 픽스처·모듈 부재를 견디는가
- run: node scripts/health.js             # 크래시하지 않는가
- run: node scripts/dashboard.js --out /tmp/d.html
```

성공 바(전부 기계 판정):
1. `health.js` **exit 0** — 크래시 0. 게이트는 `해당 없음`을 낼 수 있으나 죽어서는 안 된다.
2. 스위트 **실패 0** — 픽스처 부재는 건너뜀이지 실패가 아니다([ADR-27] 계약).
3. 산출물 **무JS 도달성** — `dashboard.html` 에서 스크립트를 제거한 뒤 뷰 전환이 성립한다.
   ([ADR-26] 계약. 단언이 아니라 **형상 검사**로 판정 — 라디오 수·축별 `:checked` 규칙·앵커 0.)

## 3. 왜 이게 새 기둥·새 도구가 아닌가

[PRO-04] 분할원리로 자기검사: (a) *어답터 없는 템플릿은 없다* ✓ — 이 레포의 존재 이유가 배포다.
(b) *기존 칸에 안 들어간다* ✗ — **팔(arm)은 이미 있는 개념**이다([TOOL-19] eval-arm 이 시나리오
A/B를 팔로 돌린다). 그래서 신규 기둥도 신규 도구도 아니고, **기존 CI에 잡 하나**다.

## 4. 반증 조건 (승인 후 — 이 절이 관측 계약이다)
- 6개월간 어답터 팔이 **한 건도 못 잡으면** 잡을 제거한다 — 상류 자기 사용이 이미 충분했다는 뜻.
- 반대로 팔이 잡은 결함이 누적되면, 그 목록이 [ADR-07] 계열(계측기 자기 눈멂)의 환경 축 사례집이 된다.
- 팔이 **오탐**(어답터에선 정상인데 실패)을 내면 성공 바 3개 중 어느 전제가 틀렸는지 먼저 적는다.

## 5. 보류 — 지금 하지 않는 것
- **여러 어답터 형상 매트릭스**(drop 안 함 / 일부만 drop)는 보류. 형상 1개가 결함 3건을 잡았으므로
  YAGNI다. 형상 하나를 통과했는데 실어답터가 깨진 사례가 나오면 그때 늘린다.
  > **재개됨(2026-08-20, 승인·이행).** 그 조건이 충족됐다 — [ADR-31]·[ADR-37]은 env 형상을
  > 통과한 상태에서 실어답터가 깨진 사례다. 원인은 **env 팔의 사본이 여전히 *상류의 데이터*를
  > 쓴다**는 것이었다(`init` 은 문서를 지울 뿐 모양을 바꾸지 않는다). 그래서 매트릭스가 아니라
  > **축을 하나 늘렸다**: `data` 형상은 표 개수·헤더 언어·마크다운 관례만 바꾸고 `init` 은 돌리지
  > 않는다(축을 섞지 않는다). 성공 바 4개는 [TOOL-26] 카드에, 실측 근거는 [ADR-40]에 있다.
  > 남은 보류는 그대로다 — drop 조합 매트릭스는 아직 근거가 없다.
- **무JS 판정을 실브라우저로**: 현재는 형상 검사로 충분하다(실측: 형상 검사 4단언이 [ADR-26]을
  재발 방지한다). 헤드리스 브라우저 의존은 zero-dep 원칙과 상충하므로 마지막 수단.
