# [PRO-24] 어답터 연결 — 배송 · 회수 · 판단

## 1. 배경 — 설문 9건이 드러낸 것은 결함이 아니라 "경로 부재"다

[WO-22a-1] 통합 설문(어답터 3곳 × 도구 3종, `eval/SURVEY-01_results.md`)과 인간 확인(2026-10-15: 동기화 0회는 **의도적
동결이 아니었다**)에서 다음이 드러났다.

| 관측 | 근거 |
|---|---|
| 어답터 2/3 이 상류 동기화 **0회**(102·129일) — 갱신 도구(`template-update`)가 그 어답터에 **없다** | 갱신 도구를 갱신으로 배송하는 구조 → 처음 못 받은 곳은 영원히 못 받는다 |
| 받은 어답터(1/3)조차 sync 가 시끄럽고 위험하다 | 로컬 발명 15개가 "상류에서 사라진 파일"로 오보 · 로컬 개조 7개가 `--apply` 를 막음 · 상류 전용 평가 스크립트(eval·adopter-arm…)가 어답터에 배송돼 CI 시간만 씀 |
| 하류가 상류보다 먼저·더 잘 만든 것이 있다 | "0건 검사 = 실패"(3/3 독립 발명) · 4값 게이트 계약 · 드리프트 감사기 · 컨테이너 머지 권한 — 상류는 일회성 설문으로만 알게 됐다 |
| 역방향 회수의 병목은 **사람이 레포마다 세션을 여는 것** | 1차 설문 3주 미답변 · 2차는 9세션을 사람이 열었다 |
| 증언보다 계측기가 믿을 만했다 | 계측기 출력은 도구와 무관하게 동일 · 증언의 사실 불일치 3건 중 2건이 틀림 · 냉독 4건이 상류 결함 6건을 찾음 |
| 지식이 레포 밖으로 샌다 | 계보 밖 교훈·환경 전제가 한 도구의 사설 메모리로(3/3; 173·30·51 파일) — 다른 도구·상류는 못 본다 |

설계 오류 자체는 고치면 된다([WO-22b-1] 등). 그러나 **상류의 구조·기능이 어답터에 닿지 않고, 어답터의 발견이 상류에
닿지 않는 한** 같은 종류의 문제는 다시 생긴다. 이 PRO 는 결함이 아니라 **통로**를 다룬다.

## 2. 원리 — 연결은 3층이고, 아래층부터 깐다

"A2A(에이전트 간 대화)를 강화한다"로 잡으면 이번에 실제로 효과가 있었던 것과 반대로 간다. 대화는 가장 비싸고(사람 왕복),
가장 재검증이 필요한(증언) 통로다. 그래서:

| 층 | 방향 | 성격 | 사람 왕복 |
|---|---|---|---|
| **① 배송** | 상류 → 어답터 | 기계. 버전·파일·앵커 | 적용 승인 1회(어답터 쪽) |
| **② 회수** | 어답터 → 상류 | 기계. 읽기 전용 계측의 **익명 집계** | 0 |
| **③ 판단** | 양방향 | 에이전트·사람. 제안·냉독 감사·단축 설문 | 승격은 사람만 |

**선택 규칙**(③의 핵심): 어답터는 상류의 OOD 벤치마크다([PRO-23] §2-C 와 같은 원리). 상류 채택 자격은
**두 곳 이상이 독립적으로 수렴했거나, 한 형상에서 다른 형상으로 옮겨도 살아남은 메커니즘**에만 있다.
첫 적용 사례: "0건 검사 = 실패"(3/3 수렴) → [PRO-22] §3 2-bis.

경계: [ADR-12] 자동 승격 금지 — 회수는 관측·제안까지. [ADR-11] 원자료는 평면에 못 들어온다 — 집계만.

## 3. 채택안 — 새 도메인 0, 스크립트 1, 설정 키 2, 생성 파일 1

### ① 배송
- **(a) 부트스트랩 키트** — `template-update` 가 없는 어답터에 넣는 최소 묶음. 지금 `template-update.js` 는 `fs_walk`·
  `gate-contract`·`init`(TEMPLATE_BITS) 를 require 해 키트가 커진다 → 드롭 목록을 JSON 으로 분리하고 `--seed`(`seedAnchor`
  는 이미 export 돼 있다) CLI 를 연다. 키트 = 파일 3개 이하 + 명령 1줄. **어답터가 끌어온다**(상류 세션이 어답터 레포를
  쓰지 않는다). 지금은 `init --apply` 만 앵커를 심는다(`clone@<ver>`) — 손으로 이식한 어답터 2곳은 그 경로를 거치지 않았고,
  그래서 앵커도 갱신 도구도 없다. 키트는 그 두 곳의 **사후 입장권**이다.
- **(b) `localOwned`** — `.union-stack/adapter.json`([ADR-29] 설정 표면, 현재 키 `private`·`zfsIgnored`)에 어답터 고유 파일 글롭을 선언. `localTemplateFiles()` 가
  이를 제외 → "상류에서 사라진 파일" 오보 0, `--apply` 가 로컬 발명을 건드리지 않는다.
  ```jsonc
  // (예시)
  { "private": true, "localOwned": ["scripts/verify.sh", "scripts/*-linter.js", "scripts/docker-ci/**"] }
  ```
- **(c) 배송 범주 축소** — 상류 전용 스크립트(eval · eval-arm · fetch-eval · scenario-rubric · token-accounting · hook-replay ·
  check-prereqs · adopter-arm · e6-workspace)는 어답터에 가지 않는다. 분류는 수기 목록이 아니라 **정의 지점 태그**
  (`// @ship upstream-only`, [PRO-21] `@test-asset` 문법)에서 생성 → `classifyPath` 가 읽는다.
- **(d)** `AGENTS.md`·`_GUIDE` 는 review 범주 유지(규칙 변경은 사람). 어답터의 AGENTS.md 는 이미 상류와 갈라져 있다(부트스트랩
  순서가 다른 곳 1) — 자동 sync 대상이 아니다.

### ② 회수 — `adopter-census.js` (읽기 전용, 사람 0)
- 입력: 형제 레포 경로 목록(이 머신의 로컬 체크아웃 — 네트워크·클라우드 없음). 목록 파일은 **비공개**(gitignore).
- 각 레포에서 읽는 것: 그 레포의 `scripts/health.js --json`(없으면 상류 health 를 `--root <path>` 로 — INFO 전용) · CHANGELOG
  헤딩 · `template-sync.json` ref·날짜 · 계측기 유무 · WO frontmatter `status:` 분포 · `evidence:` 기입률 · `upstream_candidate`
  표시된 PRO 목록(③). **코드·문서 본문은 읽지 않는다.**
- 출력 둘: (i) 원자료 JSON → 비공개 경로(커밋 안 함) (ii) `eval/CENSUS.md` 에 **익명 집계 행** append(레포 = 라벨, 형상 등급만.
  `eval/SURVEY-01_results.md` §2·§3 표가 첫 행의 꼴이다).
- 어답터 쪽 변경 0 — 이것이 "갱신 도구가 없는 어답터"도 즉시 관측되는 이유다.

### ③ 판단 — 에이전트·사람 층(이것이 A2A)
- **(a) 제안 환류**: 어답터 PRO frontmatter `upstream_candidate: true`(오버레이) → census 가 목록화 → 상류 사람이 검토.
  자동 머지 없음([ADR-12]).
- **(b) 냉독 감사를 릴리스 의례로**: `eval/SURVEY-01_adopter.md` §7 을 떼어 단축판(`eval/COLDREAD.md`) — 상류 릴리스마다
  **처음 보는 모델 1회**(이번에 상류 결함 6건을 찾은 층). 결과는 PRO 후보로만.
- **(c) 단축 설문**: §0·§1·§3(20분) — 분기 1회, 어답터 상주 에이전트가 답하고 census 가 답변 파일을 집계.
- **(d) 선택 규칙 명문화**(§2) — 상류 채택 자격 = 2곳 수렴 또는 형상 이식 통과.
- **(e) 도구 중립은 호스팅이 아니라 등록으로** — 설문에서 `.claude` 훅·슬래시·MCP 는 한 도구 전용이었고 CLI 만 세 도구 모두에서
  작동했다. 이미 있는 `scripts/mcp-server.js`(zero-dep stdio, [TOOL-05])를 각 도구(Codex·Antigravity)의 MCP 설정에 **등록**하는
  절차를 `MIGRATION.md` 에 적는다. 서버 배포는 필요 없다 — 질의 대상(평면)이 어답터 로컬 파일이라 원격 서버는 그 파일을
  읽을 수 없고, 로컬 stdio 가 곧 도구 중립 표면이다.

## 5. 하지 않는 것
- ⛔ **자동 승격 루프** — [ADR-12] 차단. census 는 관측, PRO 환류는 제안까지.
- ⛔ **원자료를 평면에** — [ADR-11]. 집계만. 어답터 코드·문서 본문은 census 가 읽지 않는다.
- ⛔ **상류 세션이 어답터 레포를 쓰는 것** — 배송은 어답터가 끌어오고(`--apply`), 회수는 읽기 전용.
- ⛔ **클라우드 에이전트 상시 순회** — 코드 반출이라 사람 판단 사항이며, 로컬 형제 레포 읽기로 충분하다.
- ⛔ **AGENTS.md 자동 sync** — 규칙 변경은 사람.
- ⛔ **대화 채널 추가**(세션 간 메시지·상시 봇) — 병목(사람 왕복)을 늘린다. ③은 릴리스·분기 주기로 고정.
- ⛔ **상류를 상시 서버로 배포**(호스팅 서비스 — 2026-10-15 검토·기각). 서버는 전송 수단만 바꾸고 문제(어답터 쪽에 앵커·갱신 도구가
  없음)는 그대로 둔다. 대신 설문에서 가장 흔했던 사고 유형("꺼진 채 4개월", "과금 실패로 CI 정지", "실행 0회")인 **조용히 죽는
  상시 구성요소**를 하나 더 만들고, 의존성 0 원칙을 깨며, 매 전송마다 반출 판단을 요구한다. 배송은 GitHub raw 가, 외부 제안 통로는
  이슈·PR(외부화된 제안 계층)이 이미 한다. **재개 조건**: 이 머신 밖(다른 사람·조직)에 어답터가 생겨 형제 레포 읽기가 불가능해질 때,
  또는 무인 A/B 런·냉독 감사가 필요해질 때 — 그때도 웹 서버가 아니라 러너(상류 Actions·클라우드 에이전트 루틴)가 먼저다.
  승인 시 이 항목은 `blocks:`/`reopen_when:` 표식([PRO-14])으로 원장에 올린다.
