# [PRO-28] 절 계약 + 부분 인출

## 1. 배경 — 같은 뜻의 절이 3~5 표기로 갈라졌고, 에이전트는 어차피 절만 읽는다

[PRO-24] 센서스 3회차가 WO 의 H2 헤딩을 처음 기계로 셌다(`eval/CENSUS.md`). 상류 발행 계약([PRO-19])은 `## 목표`·`## 수용 기준`·`## 증거` + `parent:` 넷인데,
어답터 평면은 다음과 같다.

| 레포 | WO | 상위 헤딩(빈도) | 꼬리 |
|---|---|---|---|
| A | 179 | 검증 31 · 실행 기록 20 · 실행 체크리스트 18 · 목적·진입 조건 14 · 완료 기준 13 … | 외 737종 |
| B | 233 | 증거 201 · 수용 기준 198 · 목표 186 · 계보 77 · 범위 49 … | 외 118종 |
| C | 439 | 수용 기준 203 · 비목표 133 · 진행 97 · 문제 56 · 검증 51 · 진행 기록 51 · 목적 49 … | 외 1,289종 |

B 는 상류 계약을 그대로 쓴다. A·C 는 **한 의미에 표기 3~5종**(C 의 "수용 기준" 만 4표기)이고 `## 증거` 는 **0건**(증거는 `검증`·`결과`·`실행 기록` 의
날짜 줄에 섞여 있다). 그런데도 두 레포 모두 `evidence:` 는 frontmatter 에 적는다(값 247·0건 — C 는 값, A 는 미기입).

회신 2곳(질문 3개, 원문 비공개)의 공통점:
- **통째로 읽지 않는다.** frontmatter → 목표/목적 → 수용 기준 → 꼬리(실행 기록·종료)만 grep. `배경`·`설계`·`진행 기록` 은 건너뛴다.
  토큰 최다는 WO 본문이 아니라 **절 경계 없이 연 40~80KB 급 PLAN·PRO** 와 append-only 원장 grep 이다.
- **별칭 맵으로 충분하다** — 기존 수백 건을 고치는 것은 diff·참조 비용만 크고 얻는 것이 없다. 단 `진행 기록` 은 서사이지 증거가 아니라 별칭에서 뺀다.
  증거는 대응 절이 없으니 **frontmatter `evidence:` 로 센다.** 매칭 실패는 REJECT 가 아니라 CLARIFY.
- **scaffold 는 쓴다** — 새 WO 를 직전 WO 복사로 만들어서 변종·중복 ID·빈 status 가 늘었다. 조건: 전역 **다음 번호 제안**과 **parent 실존 확인**이 같이 있어야 하고,
  뼈대가 400 tok 를 넘으면 1,500 tok 예산 안에서 짐이 된다.

## 2. 원리
- **계약은 의미, 표기는 설정.** 상류는 "목표·수용 기준·증거" 라는 *의미* 만 계약한다. 표기는 어답터가 `adapter.json` 에 선언하고 도구는 맵으로 읽는다([ADR-29] — 포크 아닌 설정). 문서는 안 고친다([ADR-25] 계열: 이미 쓰인 것은 불변).
- **읽기는 절 단위.** 에이전트가 이미 그렇게 읽고 있다면 도구가 그 절만 내주는 것이 "가장 작은 고신호 집합"이다(context engineering 1원칙). 통째 주입은 예산 밖에서만.
- **쓰기는 뼈대 단위.** 변종은 손 복사에서 생긴다. 채번·부모 확인·필수 절을 한 번에 찍는 생성기가 변종의 발생원을 막는다 — 린트(사후)보다 싸다.
- **관측 먼저([ADR-23]).** 센서스가 헤딩을 세고 있으니 맵의 효과(매칭률)는 다음 회차가 보여 준다. 강제는 없다.

## 3. 채택안 — 새 도메인 0 · 설정 키 1 · 스크립트 1 · 기존 도구 수정 3

### ① `adapter.json` `sections` — 1:N 별칭 맵 + 접두 매칭
```jsonc
// (예시)
"sections": { "목표": ["목적", "목적·진입 조건", "왜"], "수용 기준": ["수용 게이트", "수용 기준 (게이트)", "수용기준", "완료 기준"], "증거": ["검증", "결과"] }
```
키는 상류 의미(셋), 값은 로컬 표기 배열. 매칭은 **정규화(선두 번호·공백) 뒤 정확 일치 → 접두 일치**(`"목표·진입"` 이 `"목표"` 에 붙는다 — statusMap 의 첫 토큰 폴백과
같은 규약). `증거` 는 절이 없어도 frontmatter `evidence:`(별칭은 `evidenceFields`) 가 있으면 충족. `진행 기록`·`실행 기록` 류는 기본 제외(서사).

### ② 절 계약 린트는 맵을 읽는다
`work-close --table` 의 발행 린트([PRO-19])·`health` 의 관측이 `REQUIRED_SECTIONS` 를 맵으로 해소한다. **못 찾으면 CLARIFY**(어느 헤딩을 어느 의미에 붙일지 묻는다),
REJECT 아님. 상류 자신은 맵 없음 = 정확 일치(현행).

### ③ 부분 인출 — `upward-fetch --sections` · MCP `upward_fetch(sections=true)`
현행 upward-fetch 는 경로·ID 만 나열하고 본문은 에이전트가 연다(그래서 40~80KB 를 통째로 연다). 옵션이 켜지면 부모 PLAN/PRO/WO 의 **계약 절만**(①로 해소)
본문으로 주입하고 나머지는 "절 N개 · ~M tok 생략" 한 줄로 남긴다. 절 경계가 없는 문서는 머리 1,500 tok 만. 기본값은 바꾸지 않는다(관측 뒤 결정).

### ④ `scripts/scaffold.js` — `node scripts/scaffold.js WO --parent PLAN-01a [--next] [--title …]`
`--next` 는 도메인 전역 다음 번호를 **제안**(ID 산술 범위면 부모 아래 다음 자식, 레거시 범위면 최대+1 — [PRO-27] ③ 존중)하고, `parent:` 는 **ZFS 색인에서 실존 확인**
(없으면 CLARIFY, 파일 안 만듦). 뼈대 = frontmatter(status·parent·evidence·closed_by 빈 값) + 필수 절 3(어답터 표기는 맵의 **첫 별칭** 또는 상류 표기) + 선택 절 주석 1줄.
**≤400 tok** 가 성공 바. 중복 ID·빈 status 의 발생원(손 복사)을 막는 것이 목적이지 문체 통일이 아니다.

### ⑤ PRO-β 흡수 — 상시 주입 위생 둘
- **ΔC 신고**: 상시 주입 표면(AGENTS.md 마커 블록·부트스트랩)을 늘리는 PRO 는 frontmatter `injects: "+N tok — 이유"` 를 적는다. `context-budget` 이 합산해 대조.
- **압축 보존**: 예산 초과 시 압축은 재작성이 아니라 **증분 편집**이며 수치·ID·반례는 보존 대상 — AGENTS.md 1문단(Schema, 인간 승인). ACE 붕괴 실측이 근거(spike).

## 4. 분할원리 점검 ([PRO-04])
새 도메인·기둥 없음. `sections` 는 `statusMap`·`evidenceFields` 와 같은 **읽기 매핑** 클래스의 세 번째 키. scaffold 는 TOOL 카드 1장.

## 5. 하지 않는 것
- 기존 문서의 헤딩을 고치지 않는다(수백 건 diff·참조 비용). 맵은 읽기 전용이다.
- 헤딩 표기를 강제하지 않는다 — 린트는 CLARIFY 까지. "새 WO 부터 상류 표기" 는 어답터 결정(scaffold 가 돕는다).
- 본문 자동 요약·자동 압축은 없다([ADR-12]). 부분 인출은 **절 경계**로만 자르고 문장을 만들지 않는다.
- 에이전트별 "실제로 읽는 절" 통계는 수집하지 않는다(회신 2곳으로 충분 — 추가 설문은 세션 4개 값).

## 6. 성공 바
- 센서스 4회차: A·C 의 필수 절 매칭률(맵 적용 뒤) ≥ 90% · 매칭 실패 CLARIFY 가 어느 의미인지 **질문 문장**으로 나온다.
- `upward-fetch --sections` 로 연 부모 문서의 주입 토큰이 통째 주입 대비 **1/3 이하**(상류 자기 측정 — WO-24c-2 계보 ANL 2·MTG 2·PLAN 2 로 측정).
- scaffold 로 만든 WO 는 발행 린트를 CLARIFY 0 으로 통과하고 뼈대 ≤400 tok · 중복 ID 0.
- 상류 스위트에서 맵 없음 = 현행과 동일(회귀 0).

## 7. 미결 (인간 판단)
- 접두 일치의 방향: 로컬 표기가 상류 의미의 접두(`목표·진입`→`목표`)만 허용할지, 역방향(`목적`→`목적·진입 조건`)도 허용할지. 잠정: 전자만.
- `증거` 의 충족 조건: frontmatter `evidence:` 만으로 충족(회신 2곳 일치)인지, 절도 요구할지. 잠정: frontmatter 만.
- ⑤ 압축 보존 문단의 AGENTS.md 수록(Schema) 여부 — 예산 이월 9회+ 와 함께 [PRO-13] §4-4 판정.
- scaffold 의 어답터 표기 선택: 맵의 첫 별칭 vs 상류 표기. 잠정: 첫 별칭(그 레포 관행 유지).

## 8. 순서
① `sections` 파싱 + ② 린트 해소(가드 먼저) → ④ scaffold → ③ 부분 인출(옵션) → 센서스 4회차로 ①②의 효과 관측 → ⑤ 는 별도 승인.
