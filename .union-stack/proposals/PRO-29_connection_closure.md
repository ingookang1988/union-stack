# [PRO-29] 연계 완결

## 1. 배경 — 통로는 깔렸고, 아무도 그 통로를 열지 않는다

[PRO-24] 는 연결을 배송·회수·판단 3층으로 깔았고 ①②는 구현됐다(키트·`localOwned`·`localForked`·`@ship`·census 4회차).
그런데 셋 다 **사람이 기억해서 실행할 때만** 작동한다.

| 고리 | 있는 것 | 없는 것 |
|---|---|---|
| ① 상류 변화 → 하류 확인 → 사람에게 제안 | `template-update`(종료 3 = 업데이트 있음) · 3-way 보호 · `--apply` HOLD · 키트 | 트리거(하류 세션이 스스로 알 길) · 사람용 **제안문**(무엇이 왜 바뀌었나 · ⚠ 마이그레이션 · 적용 명령) |
| ② 하류 변화 → 상류 확인 → 사람에게 알림 | census(읽기 전용 · 익명 집계 · 잔여 원인 · `upstream_candidate`) | 직전 회차 대비 **델타** · **규칙 이탈** 분류 · 알림 표면 · 트리거 |
| ③ 신규·기존 프로젝트 이식 | `init --apply`(빈 레포) · 키트(손 이식 사후) · MIGRATION 매핑표(손) | 기존 문서 체계의 **자동 매핑안**(dry-run) · 적용 · 이식 직후 앵커·`adapter.json` 생성 |

실측 근거: 어답터 3곳 중 2곳이 손 이식이었고, 앵커 부재·헤딩 변종·중복 ID·빈 `status:` 가 전부 그 경로에서 생겼다([PRO-28] §1).
HANDOFF 는 여러 세션째 "셋 다 `template-update --apply` 로 받는다"를 이월 중이다 — 받았는지 상류는 모른다.

## 2. 원리 — 트리거는 세션 경계에, 알림은 이미 읽히는 표면에

- **상시 구성요소를 만들지 않는다.** [ADR-54]·[PRO-24] §5 의 기각 근거("조용히 죽는 상시 구성요소")가 데몬·스케줄러에도 그대로 선다.
  트리거는 **이미 매 세션 일어나는 일**(부트스트랩·health·세션 종료 의례)에 얹는다. 실행되지 않으면 그 사실 자체가 다음 세션에 보인다.
- **알림 = 이미 읽히는 표면에 한 줄.** 새 채널(메시지·봇)은 [PRO-24] §5 가 막는다. 하류는 자기 health·HANDOFF 진입점, 상류는 대시보드·HANDOFF.
- **제안까지, 적용은 사람.** [ADR-12]. 하류의 `--apply` 는 하류 사람이, 상류의 이탈 알림에 대한 조치는 상류 사람이(대개 어답터에게 전달).
- **신규 알림만.** 같은 이탈을 매번 다시 말하면 알림이 아니라 소음이다 — 직전 회차 대비 **새로 생긴 것**만 올린다.

## 3. 채택안 — 새 도메인 0

### ① 하류 제안 고리
- (a) **health 차원 `upstream`**: `template-update` 확인 모드를 health 가 부른다(네트워크 실패 = INFO, 판정 아님). 결과는
  "상류 x.y.z · 로컬 x.y.w · sync N · review M · ⚠ 마이그레이션 K". **캐시**(`template-sync.json` 에 마지막 확인 시각) — 24h 안이면 재조회 없음.
- (b) **제안문 생성** `template-update --proposal`: CHANGELOG 의 로컬 버전 이후 항목 요약 + ⚠ 항목의 MIGRATION 절 링크 + HOLD·localForked 목록 +
  적용 명령 1줄. 하류 에이전트는 이를 **사람에게 보이고 승인 뒤** `--apply`. 파일 쓰기 0(stdout).
- (c) **세션 의례 연결**: 하류 HANDOFF 린터가 `upstream` 차원이 "업데이트 있음"이면 다음 작업 절에 그 사실이 있는지 CLARIFY(차단 아님).

### ② 상류 이탈 알림 고리
- (a) **census 델타**: 비공개 원자료(`eval/private/`, [PRO-24] §7-2)의 직전 회차와 대조 → 레포별 "새로 생김 / 사라짐".
- (b) **규칙 이탈 분류**(고정 4종, 본문 읽기 0 유지):
  ① 어답터 게이트 red(자기 health JSON) ② 규칙 파일 분기(AGENTS.md blocks 블록·`_GUIDE`·gate-contract 의 review 드리프트 — 블롭 sha 만)
  ③ 약화 신호(어답터에 `weakening-guard` 가 있으면 그 JSON) ④ 동기화 지연(상류 대비 버전 뒤처짐 · 마지막 `--apply` 이후 일수).
- (c) **알림 표면**: 상류 대시보드에 "어답터 이탈(신규)" 카드 + census 가 상류 HANDOFF 작성 시 붙일 한 줄 요약을 stdout 으로. 익명 라벨만([ADR-11]).
- (d) **트리거**: 상류 세션 종료 의례(HANDOFF 작성 전)에서 census `--delta` 를 돌린다 — 마지막 회차가 7일을 넘으면 health 가 INFO 로 묻는다.
- 상류는 여전히 **어답터 레포를 쓰지 않는다.** 조치는 사람이 어답터 세션에 전달한다.

### ③ 이식기
- (a) **`init --adopt <existing-repo>` dry-run**: 기존 문서 트리를 헤딩·파일명만으로 스캔해 MIGRATION 매핑표를 **채운 안**(파일 → 자리 · 제안 ZFS ID ·
  확신도)과 `adapter.json` 초안(`sections`·`statusMap`·`localOwned`)을 낸다. 본문 이동·재작성 없음.
- (b) **적용**: 사람이 안을 고친 뒤 `--apply` — `git mv` 기반(이력 보존), 앵커 시딩(`clone@<ver>`), ZFS·frontmatter 린트 1회. 확신도 낮은 행은 건너뛰고 목록만.
- (c) **키트 미지원 2건 해소**: `scripts/union-stack/` 하위 설치 · `--drop-template-bits` 의 상류 전용 삭제.
- (d) MIGRATION.md "Two paths" 를 세 경로(빈 레포 `init` · 기존 문서 체계 `init --adopt` · 이미 손 이식 = 키트)로 재편.

```jsonc
// (예시) init --adopt 매핑안 한 행
{ "from": "docs/decisions/0007-db.md", "to": ".union-stack/architecture/infra/INF-03_db_choice.md", "confidence": "high", "why": "파일명·헤딩 'Decision'" }
```

## 4. 분할원리 점검 ([PRO-04])
새 도메인·기둥 없음. ① = [TOOL-21] 옵션 + health 차원 1, ② = [TOOL-30] 옵션 + 대시보드 카드 1, ③ = [TOOL-06] 모드 1. 스크립트 신설 0.

## 5. 하지 않는 것
- ⛔ 상시 데몬·스케줄러·봇([ADR-54] 근거 확장). 세션 경계 트리거로 족하다 — 세션이 없으면 바뀐 것도 없다.
- ⛔ 하류 자동 `--apply` · 상류의 어답터 레포 쓰기 · 자동 승격([ADR-12]).
- ⛔ 어답터 본문 읽기 · 원자료 공개([ADR-11]). 이식기는 **대상 레포 자신**에서 돌므로 예외가 아니다(상류로 가는 것 0).
- ⛔ 이식기의 문서 재작성·요약([ADR-12] 문법). 옮기고 이름 붙이기까지.

## 6. 성공 바 — 세 고리
**① 하류 제안 고리 — 닫힘 조건**
- 어답터 3곳 모두에서, 상류에 새 버전이 있을 때 **사람이 명령을 기억하지 않아도** 다음 세션의 health 가 `upstream` 차원으로 그것을 보인다(네트워크 없음 = INFO, 오탐 0).
- `--proposal` 제안문만 읽고 사람이 적용 여부를 결정할 수 있다 — 어답터 1곳 이상의 사람 확인(설문 1문항).
- **3곳 모두 최신 상류로 동기화된 상태가 census 로 관측된다**(동기화 지연 0 — 현행 이월 항목 해소).
  *(판정 2026-10-19, 인간 승인 — 바 재정의: "지연 0" → **"자동 적용 가능 지연 0"**. 5회차 실측: 자동 적용 가능 잔여 3곳 0 인데 census 지연 A 2 · B 12 —
  보존 포크·review(`--apply` 가 안 써서 앵커 불변)·상류 전용 사본·거부 파일은 설계상 0 이 될 수 없다. 이 바로 [WO-29a-2] 충족·Closed. 지연 분류와 health `upstream` 의
  "업데이트 있음" 을 실행 가능 항목만으로 — [WO-29a-4].)*
- *(① 상태 2026-10-19 — [WO-29a-1]~[WO-29a-4] Closed. 바 1 충족(5회차: 3곳 health `upstream` 자기 확인 도달) — 단 상시 알림 수정([WO-29a-4])의 "조용한 상태"는 하류 미관측.
  바 3 충족(자동 적용 가능 지연 A 0 · B 0 · C 0). **바 2 미확인**(제안문만으로 결정 가능한지 사람 1문항). 남은 둘이 닫히면 ① Closed — 다음 적용 회차에서 함께 본다.)*
  *(바 2 충족 2026-10-19 — 사람 확인 1문항: "2회차 적용 때 `--proposal` 제안문만으로 결정할 수 있었다". ① 의 남은 것 = 상시 알림 수정의 하류 관측 1건.)*

**② 상류 이탈 알림 고리 — 닫힘 조건**
- census `--delta` 1회로 레포별 신규 이탈이 4종 분류로 나오고, 대시보드·HANDOFF 한 줄에 실린다 — 사람 왕복 0, 어답터 변경 0.
- 주입 실험: 어답터 팔([TOOL-26]) 사본에 4종 이탈을 하나씩 심으면 **4/4 검출**, 이탈 없는 회차는 **신규 0**(같은 이탈 재보고 0).
- 마지막 회차가 7일 초과면 상류 health 가 그 사실을 보인다.
- *(② 상태 2026-10-19 — [WO-29a-5]·[WO-29a-6] Closed. 바 1 충족(6회차 실데이터: `--delta --write` 1회 → 대시보드·HANDOFF 한 줄·health·린터) · 바 2 충족(주입 4/4 → 재실행 신규 0 → 해소) ·
  바 3 충족(8일 경계 단위 테스트 — 실데이터 7일 경과는 미관측). **정밀도 결함 1**: 6회차 신규 8 중 `weak:*` 5건이 전부 오탐 — 상류가 배송한 테스트 파일 그대로(3)와
  상류가 "지워도 된다"고 한 상류 전용 사본 삭제(3, 파일 기준). 약화 판별에서 "상류 현재본과 같은 파일"·"상류 전용 사본 삭제"를 빼야 한다 — 보정 WO 대기.)*

**③ 이식 고리 — 닫힘 조건**
- union-stack 이 없는 기존 프로젝트 사본(공개 OSS 레포 1 + 어답터 팔 형상 1)에 `init --adopt` dry-run → 매핑안 high 행의 사람 수정률 ≤ 20%.
- `--apply` 뒤 그 레포에서 ZFS 린트·발행 린트 CLARIFY 0 · 앵커 존재 · `template-update` dry-run 성공(= 이식 직후 ① 고리에 들어온다).
- 빈 레포 경로(`init`)와 손 이식 경로(키트)는 회귀 0. MIGRATION 세 경로 각각을 처음 보는 모델 1회가 따라 해 완주(냉독, [PRO-24] ③(b)).

**전체 완료 정의**: 위 세 묶음이 모두 충족되고, 이어서 상류 릴리스 1회가 사람 왕복 "하류 승인 1회 + 상류 확인 0회"로 3곳에 도달한다.

## 7. 미결 (인간 판단)
1. `upstream` 확인 캐시 주기 — 24h(잠정) / 세션마다.
2. 규칙 이탈 ②의 범위 — AGENTS.md 자체 분기는 [PRO-24] ①(d) 상 "원래 갈라져 있다". blocks 블록만 볼지(잠정) 전체를 볼지.
3. census 트리거 — 상류 세션 종료마다(잠정: 7일 초과 시만 묻기) vs 릴리스마다.
4. 이식기 확신도 임계와 공개 OSS 시험 레포 선정.

## 8. 순서
① (a)(b) → 어답터 3곳 실제 동기화로 첫 검증 → ① (c) → ② (a)(b) → 주입 실험 → ② (c)(d) → ③ (c) 키트 미지원 → ③ (a) dry-run → (b) 적용 → (d) MIGRATION 재편 → 냉독.
각 단계는 [ADR-40](가드 먼저) + 어답터 팔 검증. [PRO-13] §4-4(AGENTS.md 예산)와 독립 — 병행 가능.
