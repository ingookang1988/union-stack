# E6 과제 스위트 — 결함수정 시나리오 A/B

`eval/PROTOCOL.md` §3-bis(E6)가 요구하는 과제 스위트. **팔당 총 5런**이므로 과제도 5건이고,
런 1개 = 과제 1건 = **발화 1건**이다.

## 무엇이 과제인가

이 레포에서 **실제로 났던 결함 5건**을 과거 수정 커밋에서 역산해 재주입한다. 합성 버그를 쓰지 않는 이유는
난이도가 인위적이어서다 — 실결함은 이 레포의 실제 실패 분포를 따른다.

| id | 결함 | 역산 출처 | 숨은 오라클 |
|---|---|---|---|
| D1 | 컨텍스트 예산이 한국어 문서를 과소평가 | `c3104e3` | `scripts/context-budget.test.js` |
| D2 | tools-index가 CRLF 체크아웃에서 거짓 드리프트 Fail-close | `12f5d89` | `scripts/tools-index.test.js` |
| D3 | blast-radius가 본문의 status 예시를 잠금으로 오인 | `a11f9e0` | `scripts/zfs_index.test.js` |
| D4 | 훅이 기술 토큰(UTF-8·SHA-256)을 작업 ID로 오인 | `a11f9e0` | `scripts/hooks.test.js` |
| D5 | append-only 가드가 표 데이터 행 삭제를 놓친다 | `a11f9e0` | `scripts/permission-guard.test.js` |

## 오염 차단 — 세 겹

1. **히스토리 없음.** 워크스페이스는 레포 사본에 결함을 주입한 뒤 **커밋 1개짜리 새 저장소**로 초기화한다.
   git 워크플로는 그대로 쓰되 수정 이력만 없다 — 원본 히스토리를 두면 두 팔 모두 `git log` 한 번으로 즉답한다.
2. **지목 단언 제거.** 결함을 가리키는 테스트 단언은 워크스페이스에서 걷어낸다. 남겨두면 실패 메시지가
   원인을 그대로 알려준다. 걷어낸 그 테스트가 **숨은 오라클**이고, 팔 종료 후에만 돌린다.
3. **증상만 말한다.** 발화에는 증상만 적고 원인·파일·함수·커밋 해시를 적지 않는다(테스트가 강제).

검증된 성질(빌드 시 매번 확인 가능): 워크스페이스의 **전체 테스트 체인은 그린**이고(실패가 남아 있으면
그 자체가 힌트다), 증상은 CLI에서 재현되며, 숨은 오라클은 결함 상태에서 **실패**하고 정답 복원 시 **통과**한다.

## 운영 순서 (팔 1개 = 5런)

```bash
node scripts/e6-workspace.js list                       # 과제 목록
node scripts/e6-workspace.js build D1 <팔디렉터리>/D1   # 워크스페이스 + 발화 출력
#   → 그 워크스페이스에서 **새 top-level 세션**을 열고 출력된 발화 하나만 입력한다(추가 발화 금지).
#     팔 ②는 세션 시작 시 인간이 [TOOL-17] 시나리오를 지정한다(activation: manual).
node scripts/e6-workspace.js verify D1 <팔디렉터리>/D1  # 종료 후 숨은 오라클(exit 0 = 정답)
```

D1~D5를 두 팔에 **같은 순서로** 배분한다. 팔마다 전사 디렉터리가 갈려야 하므로 워크스페이스는 팔별로 따로 만든다
(경로가 다르면 전사 디렉터리도 갈린다). 10런이 끝나면:

```bash
node scripts/eval-arm.js <①전사디렉터리> <②전사디렉터리> --n 5
```

## 한계 (정직히)

- 오라클은 *이 체크아웃의* 테스트 파일이다. 레포가 그 파일을 고치면 오라클도 바뀐다(build가 원본 HEAD를 찍는다).
- 오라클 통과는 **정답 여부**만 말한다. 절차 품질은 [TOOL-18], 비용은 [TOOL-19]가 따로 잰다.
- 결함 5건은 전부 **순수 함수 국소 결함**이다 — 다중 모듈에 걸친 결함이나 경합·타이밍 결함은 이 스위트에 없다.
  결과를 그 범위 밖으로 일반화하지 말 것.
