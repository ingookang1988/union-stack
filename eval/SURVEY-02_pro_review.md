# 초안 검토 설문 v1 — 이 레포의 상주 에이전트(claude)에게 (+ 지정된 1곳은 antigravity 도)

## 왜 묻는가 (1분)
상류가 PRO 초안 3건을 썼다. 셋 다 **어답터 쪽에서 작동해야 하는 규칙**이라, 받는 쪽 실측 없이 승인하면 1차 설문에서 본
"상류 형상에서만 맞는 규칙"을 반복한다. 묻는 것은 찬반이 아니라 **① 이 레포의 숫자 ② 무엇이 깨지는가 ③ 미결 항목에서 무엇을 고르겠는가**다.

상류 문서(읽기 전용, 로컬 경로 — 배포본 머리에 적힘): `[PRO-24]` 연결 · `[PRO-25]` 회고·정리 · `[PRO-26]` 계보 니모닉 · `[PRO-22]` v1.0 §3 · 1차 집계 `eval/SURVEY-01_results.md`.

## 답변 규칙
1. **읽기 전용.** 이 파일은 고치지 않는다. 답은 같은 폴더 `SPIKE-harness_pro_review.answer.<도구>.md`(`claude` / `antigravity`).
   테스트·CI·설정·평면 문서 불변. 커밋·푸시 없음. **같은 폴더의 다른 `*.answer.*.md` 는 열지 않는다**(이번 회차 답변끼리 블라인드 —
   1차 설문 답변 `…adopter_survey.answer.*.md` 는 열어도 된다).
   **antigravity(이 레포 이력 없음)**: §2 는 "처음 읽는 모델에게 니모닉이 도움이 되는가"를 답하는 자리다 — 적용 시험(2-1)은
   파일명·frontmatter 만으로 하고, §1·§3 의 경험 문항은 "이력 없음"으로 비운다. 사실 문항(실측 표)은 답한다.
2. 문항마다 **사실**(경로·수치·명령) · **의견** · **확신도**(높/중/낮). 모르면 "모름". 인간 판단은 "인간 확인 필요".
3. **반론 우선** — 각 PRO 에서 "깨지는 것·빼야 할 것"을 "좋은 것"보다 먼저 답한다. 근거 경로 없는 찬반은 집계에서 뺀다.
4. 계측 출력은 원문 그대로 펜스 블록. 도구가 없으면 "도구 없음" + 손계측(방법 명시).
5. 상류 ID 는 `상류 [PRO-25]` 처럼 표기. 1차 설문 답변(`…adopter_survey.answer.*.md`)은 **참조해도 된다**(이번엔 블라인드 아님).
6. **시간 상자 40분.** 우선순위: §1 → §2 → §3 → §5 → §4. 못 한 문항은 번호와 "미답(시간)"을 남긴다.
7. 경계: 답은 이 레포 spike 에 남고 상류에는 **익명 집계**만 간다.

## §1 [PRO-25] 회고·정리 — 숫자로 답할 수 있는 것부터

- **1-1 트리거 지표 실측**(파일만으로; `health.js` 가 있으면 출력 원문도):
  | 지표 | 값 | 방법 |
  |---|---|---|
  | 전체 WO 수(sprint + archived) | | |
  | `sprint/` 에 남은 Closed(또는 종결 계열) WO 수 | | |
  | Verifying WO 수 · 가장 오래된 것의 체류일(git log 로) | | |
  | 후속이 전부 terminal 인데 Crystallized 아닌 PLAN 수 | | |
  | plane sync(live·state·gap) 최신 날짜 − 최신 WO 커밋 날짜 | | |
  | LSN 수 / Closed WO 수 | | |
- **1-2 임계**: 위 실측으로 "이 레포는 지금 회고가 필요한가"를 판정하고, 지표마다 **이 레포 기준으로 맞는 임계**를 제안한다(초안 표의 20·10·10·1·30일은 추정치다).
- **1-3 체크리스트 8항**(보관·판정·상위 축 흔적·PLAN GC·교훈 후보·전략 후보·위생·기록)을 **이미 하고 있다 / 못 한다 / 빼야 한다** 로 가른다. 근거 경로. 특히 "작업마다 상위 축 갱신"이 지금 실제로 어떻게 되고 있나.
- **1-4 기록 위치**: ANL(평면 횡단, 잠정) vs MTG(PLAN 계보 공유) — 이 레포의 ANL·MTG 사용 실태(개수·용도)로 판단.
- **1-5 깨지는 것**: 이 PRO 가 들어오면 이 레포에서 깨지거나 소음이 될 것(예: Verifying 을 "라이브 확인 대기"로 쓰는 관행, 상태 어휘가 enum 이 아닌 경우).

## §2 [PRO-26] 계보 니모닉 — 적용해 보고 답한다

- **2-1 적용 시험**: 활성 계보 루트(Active/Verifying 자손이 있는 루트) 목록과 루트마다 붙일 **니모닉 후보**(2~6자). 루트가 없는 계보(전역 일련번호 WO 등)가 있으면 그 수와 처리안.
- **2-2 충돌**: 니모닉이 겹치는 경우 · 루트 우선순위(PLAN > PRO > PHASE)가 이 레포에서 틀리게 되는 경우.
- **2-3 slug 접두**(`WO-22n6-9_hr_v3_ux_recovery.md` 꼴)를 신규 파일에 적용할 때의 마찰(기존 slug 관례·길이) · 생성 뷰 렌더 `[WO-… · hr]` 가 **실제로 도움이 되는 자리**(HANDOFF · next.md · upward-fetch 출력 중).
- **2-4 `--next` 채번 보조**: 필요한가. 최근 채번 실수(`l`/`o`) 사례 수.
- **2-5 깨지는 것**.

## §3 [PRO-24] 어답터 연결 — 받는 쪽 조건

- **3-1 `localOwned`**: 이 레포가 선언할 고유 파일 글롭 목록. `template-update` 가 있으면 "상류에서 사라진 파일" 출력과 대조.
- **3-2 배송 범주**: 상류 스크립트 중 **받고 싶지 않은 것** / **받고 싶은데 못 받은 것**(1차 설문 6-0 대조).
- **3-3 census 가 읽는 항목**(health JSON · 버전 · 앵커 · 계측기 유무 · WO 상태 분포 · evidence 기입률 · `upstream_candidate` PRO)에서 **읽혀선 안 되는 것**이 있나. "원자료 비공개·집계만 평면" 규칙에 대한 의견.
- **3-4 `upstream_candidate`**: 이 레포 PRO·도구 중 상류 후보로 표시할 것(ID 와 이유 1줄).
- **3-5 키트/적용**: `template-update` 가 **없는** 레포 — 파일 3개 + 명령 1줄을 끌어올 의향과 조건. **있는** 레포 — `--apply` 를 막는 로컬 개조의 처리 선호(설정으로 흡수 vs 유지).
- **3-6 깨지는 것** · 상시 서버 기각(PRO-24 §5)에 반례가 있나.

## §4 [PRO-22] v1.0 §3 스키마 — 짧게 ([WO-22b-1] 코딩 전)

- **4-1** 선언 필드(`kind` · `env` · `cost` · 마지막 영수증 포인터)와 영수증 줄 필드(커밋 · dirty · 명령 · exit · N/M · 검사 대상 수 · env 태그 · 생성자 · `harness:`/`product:`)에서 이 레포가 **추가로 필요한 것 / 못 채울 것**.
- **4-2** "0건 검사 = 실패"가 **오탐**을 낼 검사(예: 조건부 skip 스위트, DB 없으면 전량 skip)와 그 처리안.
